# 自用 Fork：UI 风格与交互设计

这份文档记录 `lihaozhe013/pi-web` **要保留的设计意图**，不是要求永久保留当前 CSS、DOM 或组件。上游 UI 大改时，可以直接采用上游新结构，再按本文快速重做外观与交互。

适用范围：fork 皮肤、工作区、主题、工具卡片。

**分支策略**：`track-upstream` 分支长期跟随上游，本文第 6 节“适配上游大改”的流程只属于该分支。`main` 分支已改为**完全独立维护**——不再合并上游，按“极简现代”方向大幅砍功能、替换为更激进的新库；本文记录的风格与交互原则仍是 `main` 重写的设计意图来源，但具体实现、依赖与功能范围可激进重构，本文随重写更新。策略详见 [AGENTS.md](../AGENTS.md)。

## 1. 定位与取舍

- **纯自用，不是面向公众维护的发行产品。** 不为假想用户增加配置、发布流程或兼容负担。
- **明确不要 CI / GitHub Actions。** 工作流删除是有意决定，不是待补功能。开发、类型检查、测试、浏览器验收和便携打包全部本地运行；除非所有者明确要求，不要恢复 CI。
- **保留思路与风格，不保留旧实现。** 小更新优先小改；`track-upstream` 上大重构优先顺着上游重建，不为了复用旧选择器而维护平行 UI（`main` 已独立，大重构直接按自身方向重写）。
- **只改变如何呈现，不改变 agent 如何工作。** 不为视觉效果改 API、SSE、会话文件、工具执行、权限、MCP 或扩展协议。
- 不把 Pi Web 改造成 IDE，不复制整套终端模拟器；借用 TUI 的过程可见性和代码阅读体验，保留浏览器的排版、点击与触摸优势。

## 2. 视觉方向：柔和、宽松、安静的工作区

一句话：**比上游更圆润、更易读的 Web 外壳，加上 TUI 式可观察的执行过程。**

### 形状与层次

- 圆角有层级：小标记和工具卡片克制，输入框和菜单更柔和，弹窗与主要输入面更宽松；圆形和胶囊不强行改成普通圆角矩形。
- 用留白、字号、轻边框、低对比表面区分层次，不用大面积高饱和色、厚重阴影或花哨装饰抢内容。
- 侧栏与聊天区是一体化工作区，不把每个区域都做成醒目的独立卡片。
- 桌面工具栏操作采用轻量胶囊按钮，选中、按下、禁用状态可辨认；移动端保留适合触摸的图标布局，不硬塞桌面胶囊。
- 主要 composer 是一个柔和、略有抬升的输入面，聚焦时有轻描边；紧凑引用输入框不照搬大输入面的尺寸。

### 字号与密度

- 当前聊天默认字号是 **16px**（上游基准为 14px）；正文行高约 **1.75**。这是舒适阅读的基准，不是禁止调整字号。
- 工具代码、侧栏、菜单和设置页形成协调的字号层级，不把所有文字放成相同大小。工具内容使用等宽字体。
- 保留用户自己的字号、宽度和其他外观设置；不要通过升级或 CSS 覆盖把用户选择重置。
- 增加舒适度不等于无限加大留白；代码、命令、结果仍应便于连续扫描。
- 虚拟列表行高、滚动和面板宽度由上游布局机制负责；不要只改视觉高度而让布局计算失配。

### 色彩与主题

- 基础皮肤沿用上游语义变量：`--bg`、`--bg-panel`、`--border`、`--text`、`--accent` 等。工作区表面可由这些变量混合得到，不给所有主题套一组固定颜色。
- Catppuccin 是**额外可选主题**，不是替换上游主题：Latte 为浅色，Frappé、Macchiato、Mocha 为深色；以 base/mantle 表面和 mauve 强调色组织层次。
- 状态色只强调真正有意义的状态。工具卡片平时中性，不让每次成功都变成大片绿色框；错误仍需明显。
- 工具代码当前复用 Markdown 高亮所用的浅色 `vs` / 深色 `vscDarkPlus`。保留代码可读性，不要求随 Catppuccin 给每类 token 重新配色。

## 3. 仿 TUI 的过程可见性

目的不是“所有东西全部展开”，而是：**命令执行时看得见，修改成功后看得见，嘈杂的读取与搜索默认收起，用户选择永远优先。**

### 默认展开规则

以下仅适用于用户尚未手动切换的卡片：

| 内容 | 默认行为 | 设计理由 |
| --- | --- | --- |
| 一轮的 Process details | 开始展开，回答完成后也默认展开 | 工具卡片不能被父级折叠藏住，过程是聊天的一部分 |
| shell / bash / PowerShell 等命令 | 生成参数时折叠；执行开始后展开，完成或失败后仍默认展开 | 先看清执行了什么，再看结果；失败命令同样值得检查 |
| write / edit / apply_patch | 仅成功完成后默认展开 | 展示实际落地的修改，不把生成中的参数或部分输出当成成功 |
| read / search 等其他工具 | 默认折叠 | 保留步骤线索，但不让大段读取和搜索淹没主线 |
| thinking | 沿用原有独立偏好 | 不把“过程展开”变成“强制展开思考” |

补充约束：

- 用户可以随时展开或折叠；未开始或失败的写入也可以手动打开检查。
- 显式选择是三态：**未选择 / 展开 / 折叠**。不能把“用户折叠了”误认为“没有选择”。
- 默认展开由当前生命周期推导，不写成用户选择；同一轮内重新渲染、消息归档或组件重新挂载，不应覆盖已有选择。
- 当前工具选择由内存状态按 `toolCallId` 记忆，不是承诺跨页面刷新持久化；Process details 还有自己的组件生命周期，不能把两种折叠机制混为一谈。
- 部分结果仍然属于运行中；最终结果成功才是成功。patch 的失败明细也要纳入错误判断，不能只看有没有返回文本。
- 历史 shell 结果也应可读；用户直接执行的 shell 与 agent 工具卡片尽量遵循相同阅读方式。

### shell 输出：先看尾部，随时看全部

- 展开的卡片显示命令，以及现有状态所能提供的输出；不另建一套传输或执行逻辑。
- 短输出完整显示；长输出默认显示最后 **16 行**（当前 `SHELL_TAIL_LINES`）。尾部通常最接近执行结论。
- `Show all` 展示完整的现有结果，`Show less` 回到尾部；不是删除早期输出，也不是修改工具返回内容。
- 运行中空结果不必画出误导性的“无输出”完成态。
- 这里的“全部”仅指客户端已收到的结果，不承诺恢复上游工具本身截断的内容。

### 工具卡片的终端感

- 中性底色、细边框、轻量左边线、等宽命令和状态文字，读起来像连续的执行记录，而不是一串彩色通知卡片。
- 运行中用强调色和克制的光标提示；完成用勾号、失败用叉号及文字，不能仅靠颜色判断。
- 动效只是状态提示，不应为它引入持续 React 定时刷新；尊重 `prefers-reduced-motion`。
- 标题仍可折叠，键盘焦点可见；触屏上的工具标题应有足够的点击高度（当前粗指针下至少 44px）。

## 4. 工具内容高亮：只给文本加色，不重造工具视图

- read/write/edit 根据文件扩展名或文件名判断语言；shell 命令及输出使用对应 shell 的语言；patch 按各文件路径判断。
- 高亮嵌入现有文本、参数行和 diff 单元，保留上游的边框、diff 布局、行号、滚动与错误提示，不额外套一层 Markdown 代码框。
- 未知语言、普通 grep 输出、无法判断的 MCP 文本可以保持纯等宽文本，不猜成某种代码。
- 输入仍在流式生成时不高亮未完成的参数；语言按需加载，较重任务延后处理，过大文本降级为纯文本。
- 高亮是可选增强：加载失败、无法识别或性能预算不足时仍应看清原文，不能影响工具执行和结果查看。

## 6. 上游 UI 大改时怎么重做（仅 `track-upstream`）

`main` 不再跟随上游，不执行此流程；大改以按自身方向的重写代替适配。

1. 在独立集成分支保留回退点，理解并接受上游的新组件、状态与性能设计。
2. 列出新版已经实现的同类能力；直接复用，删掉 fork 重复实现，不叠加两套展开或高亮机制。
3. 先恢复舒适的字号、圆角和主题，再恢复安静的工作区表面与工具栏。
4. 在新工具组件上接回本文的生命周期展开规则、用户优先和 shell 尾部，不硬搬旧版 `MessageView`。
5. 从上游已有客户端状态适配运行/成功/失败，再接入轻量高亮；不要为了 UI 改协议或核心执行状态。
6. 按下面清单本地验收；必要时可以暂时关闭尚未适配的增强，但要注明待恢复的设计能力。

验收标准是“新版依然有同样的阅读节奏和过程可见性”，不是旧版截图像素级复刻。不要以保留 fork 为由丢掉上游修复、安全边界或性能改进。

## 7. 本地验证清单（无 CI）

按改动范围在本地运行，不需要增加自动化工作流：

```sh
npx tsc --noEmit
npm run lint
npm test
# 改动打包时
npm run test:portable
# 涉及完整交互时，按需运行本地浏览器测试
npm run test:e2e
```

浏览器验收至少覆盖相关项目：

- 默认字号与已有自定义字号；长中文、英文、代码和窄屏不重叠或截断。
- 上游浅/深主题及四种 Catppuccin；主题切换、设置预览和键盘焦点正常。
- shell：生成参数、开始执行、部分输出、成功、失败、中止、短输出、长输出、Show all/less。
- write/edit/patch：执行中不自动展开，成功后展开，失败不误判为成功；手动选择覆盖默认。
- read/search 默认收起、thinking 独立偏好；Process details 在回答前后都默认展开。
- 工具卡片在流式结束、重新挂载、历史加载、分支切换后不串用状态；并行调用彼此独立。
- diff 和代码高亮、未知语言纯文本、大结果响应速度；长记录滚动与虚拟列表几何不受皮肤破坏。
- 桌面和触屏布局、移动端软键盘、Tab 操作及减少动态效果设置。

不要在日常开发目录运行 `next build` 污染 `.next`。需要便携包时运行 `npm run package:portable`，脚本在临时目录隔离构建；没有自动发布步骤。
